# 断言台账（claim ledger）

一个只读的账本工具：把会话里「我做完了 / 装好了 / 删掉了 / 通过了」这类完成性断言，对回**同一条会话里的工具输出**，必要时再做一次**只读的现场核验**，给出三态判定。

它不评价措辞、不改写回答、不拦截回合。判定只有三种，每种都有明确的成立条件。

断言还分两种立场：**action**（「我做了什么」，第一人称或完成动词）与 **report**（「世界是什么样」）。两者都会被核，但徽章把 action 单独数——不然一堆带数字的调研笔记会把行动类淹掉。

## 三态

| 判定 | 含义 | 成立条件 |
| --- | --- | --- |
| `✓ verified` | 有机械证据 | 断言里的全部事实 token（版本号、路径、数字）都出现在**本轮或更早**的工具输出里；或现场核验通过 |
| `✗ refuted` | 有机械证据表明它不成立 | 现场核验与断言矛盾（文件不在、内容不符、registry 版本不同） |
| `? unverifiable` | 没有机械证据 | 既没有日志证据，也没有可执行的核验。**这不是失败，也不是通过** |

两条硬规则：

- 核验本身出错（命令不存在、网络失败）只降级为 `?`，**永不**记成 `✗`。推翻一个断言必须有一条真的说「不成立」的证据。
- 证据不能来自未来：后一轮的工具输出不能回头证明前一轮说过的话。

## 工具 `claim_audit`

参数（都可省略，全部只读）：

| 参数 | 类型 | 说明 |
| --- | --- | --- |
| `session` | string | 会话日志路径、会话目录或会话 id。省略则审当前会话 |
| `turns` | string | 只审指定回合，如 `"2,3"` |
| `live` | boolean | 对已知形状的断言跑一次只读现场核验，默认关 |
| `checks` | string | 一个 JSON 文件路径：断言原文 → 核验动作，用于自动形状覆盖不到的情况 |
| `recorded` | boolean | 读插件自己记的账（每回合快照），不重新读日志 |
| `stance` | `action` / `report` | 只看「我做了什么」或只看「世界是什么样」。省略则两类都返回，徽章里分开数 |
| `trends` | boolean | 读跨会话的走势（不解析日志）：每会话首现 `?` 的回合、哪类断言从没被核实过 |
| `unbacked` | boolean | 列「有完成动词但没有任何事实 token」的句子——它们从不进台账（最多 200 条，展示 60 条） |
| `errors` | boolean | 看记账自身的错误尾巴 `errors.log`：记账失败不会打断会话，只写这里 |
| `limit` | number | `errors` 取多少行，默认 20 |
| `badge` | boolean | 直接返回客户端徽章用的原始数字（JSON），用来核对徽章与最近一次审计是否一致 |

`checks` 指向的 JSON 除了「原文 → 核验」的精确匹配，也收 `{ "rules": [{ "pattern": "...", "flags": "i", "check": {...} }] }`：一类说法写一条正则。写错的正则会被跳过，不会让整次审计失败。

返回一张表加一行 badge，例如：

```
claims 3 · ✓ verified 1 · ✗ refuted 1 · ? unverifiable 1
```

`live` 能跑的核验是一个封闭词表：路径存在 / 路径不存在 / 文件包含、文件是否干净（严格 UTF-8、无 BOM、无 U+FFFD）、npm registry 上的版本，以及只读命令白名单（node、git、python、python3、curl）。

## 配置

| 键 | 默认 | 说明 |
| --- | --- | --- |
| `enabled` | `true` | `false` 时工具仍可用，但不再自动记账（不订阅会话事件） |
| `dir` | `""` | 台账目录，空则 `~/.dsh/claim-ledger` |
| `debounceMs` | `250` | 同一会话的重复 `turn/end` 合并成一次 |
| `live` | `"local"` | 自动档的核验强度；`"none"` 只做日志内取证 |


## 写入取证

「我把 X 写好了」的证据不在工具回执里——`write` / `edit` 的回执通常只有 `Updated file`，路径只存在于**调用参数**里。所以插件把 `tool/call` 的 `arguments` 收进来作为第二证据通道，只对写入族工具（`write` / `edit` / `multi_edit` / `apply_patch`）生效：

| 情况 | 判定 |
| --- | --- |
| 入参里出现该路径 + 文件存在 + 文件干净 | `✓ verified`（live） |
| 入参里出现该路径 + 文件不存在 | `✗ refuted`：写了但东西不在 |
| 入参里出现该路径 + 文件在但内容坏了 | `✗ refuted`：写了，但写坏了 |
| 入参里没有该路径（哪怕文件确实在） | `?`：没有写入动作，文件在也说明不了什么 |

最后一条是这次改动的重点：以前带「写好了」的句子会被通用存在性核验接管，文件在就 `✓`——那恰好是最容易骗过人的情况。

不覆盖：用 shell（`pwsh` 等）写文件、子代理写的文件、句子里的相对路径。这些一律留 `?`，不猜。

## 自动记账

每个回合结束时（会话事件 `turn/end`），插件拿**内存里这个会话的事件**算一次台账并落盘，不需要谁去调工具：

```
~/.dsh/claim-ledger/<sessionId>.json   最新快照：每回合计数 + 全部断言
~/.dsh/claim-ledger/journal.jsonl      每回合一行，用来看走势
~/.dsh/claim-ledger/errors.log         记账自身失败的地方（平时不存在）
```

- 自动那一档**只跑本机文件核验**（路径存在 / 不存在、文件包含、文件是否干净）：不发网络请求、不起进程。所以自动账里的 `?` 比手动 `--live` 更多，这是刻意的。
- 插件在会话中途加载时，会用日志补一遍历史事件，并把这个会话的日志路径记进快照；补不上时重试，不重试就说明日志确实还没落盘。
- 没有开关，想让它闭嘴就停用插件。它不写会话、不改对话、不拦回合。

## 走势

单轮台账回答「这句当时被核了吗」。走势回答另外两个问题，读的都是已落盘的数据（`journal.jsonl` + 每会话最新快照），不重新解析日志：

1. **这个会话从第几个回合开始出现 `?`**——早出现通常说明取证没跟上，而不是有人在谎报。
2. **哪类断言从没被核实过**（按 立场 × token 类型 分：行动/陈述 × 版本号/路径/数字）。

本机实测：`行动·路径` 分类曾经 5 条全是 `?`。逐条打开后发现，其中 2 条是 `D:\…docx` 这种**省略号截断的路径**（被当成真路径去探存在性，得出「本机没有这个路径」），3 条是「我装不了」这类**否认类**断言的转述。修掉这两处后降到 3 条，剩下的 `?` 每条都有如实的理由。

```
node cli.mjs trends            # 或 claim_audit({trends:true})
```

## 覆盖率

台账只会记录带 token 的句子，「改好了」「README 里也写好了这一节」这类话根本不进表。所以表格末尾会多一行：

```
完成性断言 15 句 · 有 token 可查 1 句（7%）· 没有 token 14 句（不进表，未取证）
```

它是在说：这期我说「我干完了」15 次，其中 1 次能被查，14 次连查的把手都没有。`badge` 后面同样带 `· 覆盖 7%`。统计口径排除了条件句（「跑通了再谈」）与第三人称（「作者迁移了」），但仍是从宽的口径——**这是覆盖率的上界**。

## 跑通类断言

「测试跑通了」「构建通过了」没有版本号也没有路径，以前连表都进不去。v0.6.1 起，这类句子靠**同一回合执行类工具（`pwsh`/`shell`/`node`/`npm`/`python`/`git` …）的输出**取证：

- 输出里写了 `N failed` 且 N > 0 → **被推翻**（即使同时有 `5 passed`）；
- 有成功标志（`N passed` / `all tests passed` / `0 failed` / `全绿` / `build succeeded`）且这份输出没有别的失败字样 → **已验证**，证据标 `tool`；
- 只有失败字样 → 留 `?`，不推翻；
- 本回合没有执行类输出 → 留 `?`，note 写「测不到」。

只看本回合，且只证明「这一回合有成功标志」，不证明整条链路。覆盖率的分子也把这类算进去了（15 个真实会话里 28 条跑通断言，4 条通过、24 条测不到）。

## 徽章与面板

输入框下面有一行小徽章，点开是这张会话的完整台账：

```
台账 71  ✓59 ✗0 ?12   行动 14   覆盖 6%  ▾
```

展开后上面是分类计数，下面是**逐条断言列表**：每行 `t13 行动 ✓ 我把 README 重写了。`，
判定用颜色区分，下面附该条的核验说明（为什么是 `?`、哪条核验跑成了什么）；
可用「全部 / 行动 / 陈述 / ✗被推翻 / ?测不到」筛选。

- 数据走宿主的**投影**（`sessionProjections` 的 `wire`，key `claim-ledger`，`stateVersion: 2`），不读文件、不起 HTTP 路由——起本机路由等于给任何网页开一个无鉴权读接口。
- 徽章与自动记账共用**同一份**内存台账：谁先到谁算，另一个直接读结果，所以两处数字不会打架。
- 面板最多带最近 300 条（`PANEL_CAP`），更早的在面板底部报数；要全部条目就用 CLI 或 `claim_audit`。
- 只在进过一个回合之后才出现；改 `client.js` 之后要**刷新页面**才会重新加载。
- 2026-11-26 在 Web GUI 里刷新后确认可见（截图：`台账 71 ✓59 ✗0 ?12 行动 14 覆盖 6%`）。
- 徽章的边界与工具输出一致：`?` = 没有可执行核验，不是通过。

## 边界（重要）

- **自动核验只覆盖不会误判的形状**：带「已删除 / 已清理」的路径断言、带「成品在 / 备份在 / 另存」的路径断言，以及**写入族工具入参命中**的写文件断言。其余一律留在 `?`，靠 `checks` 文件补。这是刻意的取舍：宁可漏判，也不要让一个假的 ✓ 洗白整段话。
- **`?` 不等于通过**：纯链接、没有动作词的句子不判定；「预览图在 X.png」这类只写了文件名没写路径的句子也不判定。
- **探针只认存在、不认不存在**：带本机路径、又没匹配上自动核验动作时，会做一次 `path_exists`。存在 → `verified`（只证明路径在）；不存在 → 留 `?`，因为没声明是自己刚创建的东西，缺失可能就是预期。纯 markdown 链接里的路径一律不探。
- **`✓` 只保证句子里可执行的那部分**：它核的是版本号 / 路径 / 数字这些 token，不核「我装不了」「已经修好」这类没有 token 的半句。一个 `✓` 不代表整句话成立。
- **省略号截断的 token 不是事实**：`D:\…docx` 标成 `elided`，不要求它出现在输出里，也绝不拿它去探路径（否则会得出「本机没有这个路径」这种误导性的附带结论）。
- **引号里的话不算这句的立场**：转述「我装不了」不是我在声明做不到，所以 `stance` 只看引号外；但否认类判定不分立场，转述的「我装不了」同样不能用路径存在来支持。
- **否认类断言（「我装不了」「跑不通」「失败了」）不能靠日志升级**：token 出现在输出里只证明那个名词存在，证明不了做不到。这类句子要么有报错输出（含 error / denied / EACCES 等），要么留 `?`。
- 抽取只保留**带事实 token** 的句子。没有版本号、路径、数字的「已完成」不会被记账——所以数字为 0 不代表这句话可信。覆盖率那一行就是为了不让人误以为「表里全绿 = 我说过的都验过了」。
- 它不是门禁：没有非零退出码，不会因为出现 `✗` 就拦住任何事。是否改写、是否补救，由看到账本的人决定。

## 安装

插件市场之外，也可以直接从本地目录安装：Plugins → Add plugin → 选择这个目录。安装后 `claim_audit` 出现在工具列表里。

命令行同样可用：

```
node cli.mjs audit samples/demo-session.jsonl --live --checks samples/demo-checks.json
```
